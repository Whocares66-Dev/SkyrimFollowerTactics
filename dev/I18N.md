# The panel in other languages

Built 2026-09-22 on `wip-i18n`. English (en-US) is the source; Simplified
Chinese (zh-CN) is the first catalog, as a test of the whole path. Not yet
seen in game.

## How SKSE mods localise, and what this one does

There is no single SKSE convention. What the field does:

- **The game's own translation files.** `Interface/Translations/<Mod>_<LANGUAGE>.txt`,
  UTF-16 LE with a BOM, one `$KEY<tab>text` per line; `<LANGUAGE>` is the
  ini's `sLanguage:General` (ENGLISH, CHINESE, ...). The Scaleform
  translator resolves `$KEY` in any Flash menu, which is why SkyUI MCMs and
  the mods built on them use it, and why translation tools (xTranslator,
  ESP-ESM Translator) read it. CommonLibSSE-NG wraps it:
  `SKSE::Translation::ParseTranslation(name)` loads a mod's file into the
  translator and `Translate(key, out)` looks a key up (in UTF-16, converted).
- **A file of the plugin's own.** ImGui mods have no Flash menu, so the
  translator buys them nothing. SKSE Menu Framework itself keeps its words
  in `SKSE/Plugins/SKSEMenuFrameworkStrings.json` beside
  `SKSEMenuFrameworkStrings_PT.json`, and since 3.18 a missing line falls
  back to English.
- **None.** Most ImGui mods ship English only.

This panel is ImGui, so the Scaleform route would mean symbolic `$KEY`s
for a thousand lines, a UTF-16 file and a conversion per lookup, for no
menu that could use them. It takes the second route, gettext's shape:

- **English is the key.** `Tr("Rules")` is "Rules" until a catalog says
  otherwise. A missing file, line or empty entry reads in English, never as
  a blank or a key. The code reads as it did.
- **A catalog is flat JSON, UTF-8:** `{"Rules": "规则"}`, at
  `Data/SKSE/Plugins/FollowerTactics/Translations/<locale>.json`.
- **The language** is the ini's `[Interface] language` (`zh-CN`), or with
  `auto` (the default) the game's `sLanguage` mapped to a locale
  (`core/I18n.cpp`, `LocaleFor`: CHINESE is zh-CN). Read once at data loaded,
  before the panel adds its menu entries, whose names are translated and
  cannot be renamed after (`game/I18n.cpp`).
- **The log stays English**, for bug reports. So do names the game gives
  (items, spells, followers, perks): those are already in the player's
  language, from the game's own strings files.

## Fonts

ImGui draws only the glyphs its font atlas was built with, and the atlas is
SKSE Menu Framework's, not ours:

- **3.17 and later** read the game's own SWF fonts for the game's language,
  with a glyph range setting, so a Chinese game shows Chinese as it is.
- **Before 3.17** (the test instance has 3.14.1): `SKSEMenuFramework.ini`
  `[Fonts] EnableChinese = true` adds ImGui's Chinese range to the one
  font it loads, `PrimaryFont`, a file in `Data/SKSE/Plugins/Fonts`. It
  merges nothing: the primary font itself must carry Chinese. The default,
  `MainFont.ttf`, is not shipped, and its fallback, `SkyrimMenuFont.ttf`,
  has no Chinese, so with `EnableChinese` alone Chinese reads as `?`
  (seen 2026-09-22; the framework's log says only that the primary font
  fell back).

To test on the test instance: `language = zh-CN` in `FollowerTactics.ini`,
and in `SKSEMenuFramework.ini` `EnableChinese = true` with `PrimaryFont =`
a CJK .ttf in `Data/SKSE/Plugins/Fonts` (the test mod carries SimHei as
`CN.ttf`: a system font, for local testing only, not to be shipped). It
changes the font of every mod's pages.

## Marking a line

`src/core/I18n.h`. Three marks, and `tools/i18n.py` extracts all three:

| | |
|---|---|
| `Tr("Rules")` | translated here. `const char *` in, `const char *` out; a `string_view` overload too. |
| `TrFormat("{} of {}", a, b)` | translated, then formatted with `std::format`. A translation may reorder: `"{1} 中的 {0}"`. One that does not format with the arguments is passed over for the English. |
| `N_("Rules")` | marked only, for a literal in a table; translated where drawn, `Tr(DisplayName(kind))`. |

The rules:

1. **Only what the player reads**: labels, headings, tooltips, buttons,
   column headers, messages and reasons shown on a page, a breakdown's line
   names. Not the log, JSON keys, wire names, ImGui ids, `%s`, file paths,
   engine identifiers (condition function names, EditorIDs, actor value
   names the engine spells), or anything compared as a value.
2. **Never a translated printf format.** A translator's `%s` out of place
   would read the wrong argument. `Im::Text("%s rules", n)` becomes
   `Im::TextUnformatted(TrFormat("{} rules", n).c_str())`; `Im::Text("%s", Tr(...))` is fine.
3. **A sentence is one line.** `"Base " + name` becomes `TrFormat("Base {}", name)`:
   a language may put the name first. Fragments that join into a sentence
   cannot be reordered by a translator.
4. **The mark goes on the literal.** `Tr(on ? "a" : "b")` is not extracted:
   write `on ? Tr("a") : Tr("b")`.
5. **An id stays out of the text.** `"Delete##rule"` becomes
   `std::string(Tr("Delete")) + "##rule"`.
6. **A width measured for a label** measures the translated label.
7. **English plurals** stay two lines: `n == 1 ? Tr("1 rule") : TrFormat("{} rules", n)`.
   A language without plurals translates both alike.

## Keeping catalogs in step

    python tools/i18n.py          # rewrite assets/Translations/*.json
    python tools/i18n.py --check  # exit 1 if out of step, or a translation's fields differ

`en-US.json` is the extracted list, each line its own translation: what a
translator starts from. Every other catalog keeps its translations for
lines still marked, gains an empty entry for a new line, and loses a line
no longer marked. Lines are in the order the source first marks them.

## Where it stands

- 728 lines marked across the panel, core's vocabulary and verdicts, the
  sheet, magic, inventory and Progression's messages; zh-CN translates all
  of them. The build is clean and the core tests pass; nothing seen in game.
- **One key, one translation.** A word used in two senses shares an
  entry: "Light" is both the spell archetype and the armour weight (the
  armour reads "Light {}", so it is apart), "Cast", "Target", "Voice". The
  zh-CN catalog picked the likelier sense. If one reads wrong in play, the
  fix is a context mark (gettext's msgctxt, e.g. `TrIn("armor", "Light")`)
  -- not built.
- **Plurals** are English's two lines; a language with more forms
  (Russian, Polish) would want a per-locale rule. Not built.
- The log stays English, except the HUD notices Progression also logs
  (`Refuse`), which log what they show.
