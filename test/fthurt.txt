; ============================================================
;  FollowerTactics - drive the SELECTED actor to a test threshold
;  Run:  bat fthurt      (with the follower still selected)
;
;  forceav sets CURRENT health without touching max/base.
;  Do NOT use setav/modav here - those move max health and break
;  the very percentage the rule engine reads.
;
;  WHY 25, AND NOT SOMETHING LIKE 100:
;  a console batch file cannot do arithmetic, so it cannot say
;  "40% of max". An absolute number has to be low enough to be a
;  small fraction at ANY level. Lydia levels with the player from
;  a floor of 6, where max health is roughly 120-130, and climbs
;  from there. 25 trips a 50% or a 30% rule on any character.
;  An earlier version used 100, which on a low-level follower is
;  around 77% of max - it would fail to trip a 50% rule while
;  looking exactly like a broken harness.
;
;  It is deliberately NOT 1: a hair from death she may drop into
;  bleedout, a different state and a different code path.
; ============================================================

; --- Before ---------------------------------------------------
getavinfo health

; --- Hurt them ------------------------------------------------
forceav health 25

; --- After ----------------------------------------------------
; Read "current" against "base": that ratio is exactly what
; Snapshot::health.Pct() computes in Phase 1.
getavinfo health

; NOTE: the health BAR will not redraw. forceav writes the actor value
; directly and does not raise the HUD update that real damage does, so the
; bar keeps showing the old value until she is actually hit. The number is
; correct; the display is stale. Trust getavinfo and the mod's log, not the bar.
;
; Health regen starts pulling this back immediately.
; If you need the value to hold still long enough to observe,
; freeze AI first with tcai (toggles for ALL actors).
;tcai
